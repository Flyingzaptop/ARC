# ARC IR v0

ARC IR v0 is the renderer-neutral record produced at the application-facing graphics boundary. The first producer is the D3D12 frontend. Object and work IDs are process-local, monotonic integers. Native pointers are lookup keys only; destroying an object removes the lookup, and reuse of the pointer receives a new ID.

`Runtime` in `include/arc/arc2/runtime.hpp` holds mutable command-list state. `record_work` copies the entire `PipelineSnapshot` at the API call. It records pipeline, graphics and compute root signatures, shader IDs, descriptor heap IDs, root bindings, vertex/index buffers, render/depth targets, and scissor. Raster, depth and blend flags start unknown. Root constants are copied by value. A command-list reset increments its generation and clears state/work; a submitted work item keeps its captured generation. A bundle execution is explicit symbolic work until its effects can be expanded safely.

The source now defines typed `WorkArguments` for draw and indexed-draw counts, starts and signed base vertex; dispatch X/Y/Z; indirect signature, maximum count, argument/count buffer identities and offsets; and clear target plus exact signature. Missing payload is `monostate`, serialized with `known:false`, not a guessed zero. Indirect payload tracks whether a count buffer was actually supplied, separately from whether its object ID resolved. Clear target validity is captured at the call. Serialized schema 1 declares `command_payload_version:1`; older schema-0 records must not be interpreted as if they contained these values. The focused portable IR test passed; the owned native binding test verified exact dispatch payloads in the schema-1 dump and checked GPU output. Draw and indirect payloads do not yet have equivalent native assertions. Native forwarding continues to use the original application arguments.

`BufferBinding` now distinguishes an omitted vertex stride or index format from a known value of zero; index format carries a namespace tag (`1` for raw DXGI values). Full scissor rectangles retain literal left/top/right/bottom coordinates, including negative coordinates, with `scissors_known` separate from a known-empty list. The older single `scissor` field is a compatibility projection of the first rectangle only when its width and height fit signed 32-bit integers. The focused portable IR test passed for zero versus omitted IA fields, literal rectangles and known-empty versus unknown scissors; these fields do not yet have equivalent native assertions. They do not make IR a replayable command stream: indirect signature layouts, shader effects, bundles and all auxiliary command semantics remain unresolved.

Each root constant word has a parallel `constants_known` bit. Sparse writes leave gaps unknown even though the backing vector contains zero placeholders. Captures are limited to 64 words per parameter; larger offsets/counts set `constants_overflow` and `incomplete`. Switching to a different root signature clears the affected root bindings.

`ResourceShape` retains known dimension, width/height/depth, array and mip counts, sample count, format, flags and allocation kind. `format_namespace=1` means DXGI_FORMAT IDs and `flags_namespace=1` means D3D12_RESOURCE_FLAGS IDs; zero means opaque/unknown and is not forwarded as a native interpretation. The graph bridge maps these fields to the existing resource record. It leaves absent shape data unknown.

`FixedPipelineState` is registered per PSO, copied by `set_pipeline`, and frozen into each work item. A producer sets `raster_known`, `depth_known`, `blend_known`, or `topology_known` only when all state fields relevant to that facet are captured. Numeric normalized values use: fill `0 unknown, 1 solid, 2 wireframe`; cull `0 unknown, 1 none, 2 front, 3 back`; compare `0 unknown, 1 never, 2 less, 3 equal, 4 less-or-equal, 5 greater, 6 not-equal, 7 greater-or-equal, 8 always`; topology type `0 unknown, 1 point, 2 line, 3 triangle, 4 patch`. Other numeric blend/logic/stencil values need an explicit producer mapping before a facet may be marked known. Raster state includes bias/clamp/slope, conservative raster, multisample, antialiased line, and forced sample count. Stencil front/back operations and eight blend targets are retained. Dynamic viewports, primitive topology, blend factor, stencil reference, scissor, and shading rate are command-list state; floating values are serialized by IEEE-754 bit pattern.

A descriptor reference is `(heap ID, slot, generation)`. A write or copy increments the destination slot generation. Root signatures can declare typed parameters and descriptor ranges with register space, register index, count, and table offset (`UINT32_MAX` means APPEND). Shader bindings can declare register space/range and dynamic indexing. An intersecting table binding yields a symbolic descriptor interval `(heap, first slot, count)` clipped only for an unbounded range with a known heap size. A finite range extending beyond the heap becomes unknown. Samplers do not create resource accesses. The table base alone never proves an exact resource access. Shader declarations can also be attached to a shader ID as known, symbolic, or unknown `Access` entries. Unknown access and unsupported calls remain explicit, and an unsupported call poisons rewrite eligibility on that list until reset.

Submissions capture a queue and ordered work IDs. Queue order and signaled/waited fences create submission dependencies. A wait whose signal is unavailable is unsatisfied and marks the current snapshot incomplete; a later captured signal can resolve the edge. Transitions retain raw before/after values and a `known` bit; alias barriers are explicit. Presents are recorded only for successful non-test calls and include swapchain generation, backbuffer ID, result, and last known queue submission. Resize increments swapchain generation. Work-to-Present reachability is only asserted through a captured queue submission, never inferred from frame timing.

The runtime retains a rolling window of work items and submissions. Monotonic `total_work` continues counting after the window rolls. `history_truncated` and `dropped` disclose unavailable history; `incomplete` means a semantic capture gap, including a command list larger than its active-recording cap. A *detected* descriptor generation change between recording and submission sets that submission's `complete=false` and increments `uncertain_submissions`; earlier submitted work is not rewritten retroactively. `serialize` emits stable JSON in ID/insertion order without pointer values.

Each recorded work item is immutable after its API call. Active command lists, the rolling work history, and observer snapshots share that record; reset or retirement releases only the relevant references. Submission, fence, transition, and Present histories retire their oldest entries in constant time. Snapshot serialization retains the same IR field order and values.

## Safety boundary of the current bridge

`Submission.complete=true` means that the command list was available at submit, no unresolved queue wait blocked its recorded ordering, and the descriptor references **checked by the current implementation** still matched. It does not certify a closed resource dependency set or completion on the GPU. For root descriptor tables, `descriptors_current` checks the table-base slot generation, not every non-base slot in a declared interval. A later write to another slot in that interval can leave `complete=true`. The D3D12 frontend reflects declared shader ranges as symbolic intervals and currently marks reflected bindings as potentially dynamically indexed; it does not resolve which descriptor the shader actually reads or writes. Neither `complete=true` nor a symbolic interval proves the resources inside that interval are unchanged or actually accessed.

`feed_resource_graph` forwards only `Certainty::Known` accesses from submissions marked complete. It drops symbolic and unknown accesses; a graph containing a known render-target edge can therefore still lack shader input edges from the same draw. It also does not currently emit descriptor-view history, resource destruction, heap sizes, or copy-specific graph events. A `ReadWrite` access is forwarded as a write event, so the graph's read count omits that side. Retained-history eviction can leave a submission whose work IDs no longer have work records in the current snapshot. Bridge event timestamps are synthetic sequence ordinals, not measured time; its unset `draw_items` and `dispatch_groups` counters mean unavailable totals, not zero GPU work. These omissions make the graph a partial read-only analysis projection, not a proof of complete dependencies or cost. It must not drive memory eviction, aliasing, residency, or other resource-changing actions until the required dependency closure is independently established.

The current ARC 2 mutation is limited to consecutive identical RTV clears with the same known descriptor generation and exact color/rectangle signature. It does not rewrite work based on descriptor-table contents. The observer path currently builds `ResourceGraph`, runs resource semantic classification and scene summary, and stores diagnostics; those outputs are read-only. No measured reduction in unknown dependency rate is implied by this schema description.

A `Clear` work item records the application's API request. In optimize mode, the clear admission callback can skip forwarding a redundant second clear to native D3D12 *after* that item has entered IR. The requested-work count and the bridge's corresponding resource-use count can therefore exceed executed GPU clear work. `accepted_actions` is a separate aggregate count; it is not a per-work execution flag or a per-work native cost measurement. Until execution status is recorded per work item, no timing or savings should be attributed to a particular recorded clear from IR counts alone. GPU marker/event calls are forwarded without work or state records; this also limits attribution of executed work within marker ranges, while preserving the markers themselves.

The current command-list frontend forwards `SOSetTargets` without recording its stream-output buffer bindings. Draw snapshots with stream output can therefore lack a GPU write dependency even when their submission is otherwise recorded. This blocks dependency closure for those draws and any future memory action based on them. The current consecutive-RTV-clear rewrite does not use stream-output binding evidence.

Minimal regression cases before using wider IR policy: record a two-slot SRV table, overwrite the non-base slot before submit, and require an uncertain submission or a narrower definition of `complete`; combine a symbolic shader SRV with a known RTV and verify the bridge never reports dependency closure; verify `ReadWrite` and copy events retain both sides of their meaning; exercise a submission whose work was evicted from the rolling window. Floating fields are emitted as unsigned IEEE-754 bit patterns rather than JSON nonfinite literals. The portable test covers NaN, signed zero and infinities in blend factors; viewport nonfinite inputs still lack an explicit assertion.

Current limitations: table ranges, dynamic indexing, enhanced barrier semantics, full shader reflection, viewport/raster/depth/blend state, indirect argument layouts, cross-process synchronization, and exact GPU completion are not universally captured. An API frontend must call `unsupported` for unmodeled commands so optimizer policy abstains. This v0 schema is deliberately narrower than complete D3D12 semantics.
