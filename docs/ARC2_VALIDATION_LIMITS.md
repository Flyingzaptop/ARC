# ARC 2 validation limits

This is a coverage map, not a completion certificate. The five passing owned tests in [final-owned-tests.txt](evidence/arc2-20260930/final-owned-tests.txt) cover one portable IR fixture, one CPU-meter test, and three small GPU fixtures. They do not constitute five independent engine tests. External workloads, modes, quality and performance evidence are tracked separately in [ARC2_TEST_MATRIX.md](ARC2_TEST_MATRIX.md) and [ARC2_RESULTS.md](ARC2_RESULTS.md). A native call forwarding successfully does not prove its semantic IR is complete.

| Requested check | Direct evidence in this repository | Limit of that evidence |
| --- | --- | --- |
| COM identity and lifetime | `arc2_binding_native.cpp` checks `GetDevice`, `SetPrivateDataInterface` and scalar private data; `arc2_native_lab.cpp` exercises wrapper creation/release and resize. | Not an exhaustive IID/lifetime matrix. Native-supported Device6–14 and other interface escapes remain coverage gaps. |
| Resource IDs and pointer reuse | `arc2_ir_tests.cpp` destroys a resource and reuses its native pointer key; IDs differ. | Portable runtime test, not native COM allocator reuse under a real game. |
| Descriptor generations, copies and overwrite | Unit test writes, copies, overwrites and checks generation; another test marks a base descriptor changed before submit uncertain. | No native test of every copy range or non-base slot mutation in a symbolic table. `Submission.complete` is not dependency closure. |
| Root tables, constants, PSO/root switching | Unit tests check typed ranges, APPEND offsets, overflow, sparse constants, same/different root signatures and state snapshots. `arc2_binding_native.cpp` dispatches with two SRVs, a UAV, root constants and two PSOs, then checks GPU readback and parent identity. | Native fixture exercises a compact compute case, not all shader stages, root descriptors, bindless indices or every PSO stream form. Root CBV/SRV/UAV descriptors lack a dedicated native result test. |
| Shader dynamic indexing and bindless access | Unit test retains symbolic intervals, including a dynamic declaration, and rejects a range beyond heap bounds; native binding fixture yields an IR dump. | Reflection declares possible ranges; it does not identify actual indexed descriptors. No native bindless stress proof or shader-effect closure. |
| Command-list reset/reuse, bundles | Unit tests verify reset clears captured state and a bundle execution remains symbolic. Native lab resets/reuses a direct list every frame. | No dedicated native bundle execution or inherited-state correctness comparison. |
| Draw/indexed/dispatch payloads and IA/RS detail | The focused portable IR test passed for typed counts/starts, signed base vertex, dispatch X/Y/Z, vertex stride, index format and literal scissor arrays. The owned native binding test checked exact schema-1 dispatch payloads and GPU readback. | No equivalent native assertions yet for draw/indexed payloads or IA/scissor fields. Payloads do not prove shader effects or make the entire stream replayable. |
| Multi-queue, fence order | Unit tests create two queues, signal/wait edges and wait-before-signal resolution. Native lab uses one direct queue and a fence. | No native cross-queue synchronization, external fence, or queue-race validation. |
| Indirect arguments | The focused portable IR test passed for signature ID, maximum count, argument/count buffer IDs and offsets, including count-buffer presence and unresolved identities. | No equivalent native indirect assertion yet. Indirect command signature layout, actual count and executed argument effects remain symbolic. |
| Legacy barriers | Unit transition record and native lab backbuffer state transitions; binding fixture includes UAV and transition barriers. | Only these barrier forms are directly exercised; no full subresource state-machine proof. |
| Enhanced barriers | Listed as unsupported in [ARC2_ARCHITECTURE.md](ARC2_ARCHITECTURE.md). | Later command-list revisions and enhanced-barrier semantics are not exposed or natively validated. |
| Placed/reserved resources and aliasing | Frontend has creation forwarding and IR allocation/alias representations; unit bridge checks resource shape and a committed allocation. | No dedicated native placed-resource, reserved-resource or aliasing safety proof. An alias barrier is not a license to rewrite memory. |
| ResizeBuffers, Present, teardown | Native lab resizes midway, reacquires backbuffers, checks successful Presents and final readback; unit test checks Present generation and ignores positive/nonzero or failing HRESULTs. | Does not establish full DXGI transparency across formats, flags, swap effects or long teardown sequences. |
| Unsupported calls fail closed | Unit test poisons a command list after `SetPredication`; optional interface coverage is tracked separately. Architecture lists mesh, DXR and modern interface gaps. | Unsupported mesh/DXR calls may forward with unknown-effect records; this is not semantic support or a tested optimization surface. |
| IR serialization and deterministic ordering | Unit test compares repeated serialization, checks root data and symbolic metadata, and tests rolling retention order. | No exhaustive roundtrip decoder test or long-session schema compatibility guarantee. |
| Rewrite, quality and rollback | Native lab records repeated identical RTV clears, validates accepted-action count, toggles optimization off, captures GPU readback and debug output; [quality.json](evidence/arc2-20260930/native-lab/quality.json) reports exact modified and rollback images for that fixture. | Only the owned consecutive-clear rewrite has this admission evidence. Temporal visibility, visual importance, perceptual control and memory actions are not migrated into ARC 2. |

The current bridge sends only known access edges from submissions passing its limited consistency checks to `ResourceGraph`. Symbolic table contents, stream-output bindings, some copy/view/lifetime evidence, and non-base descriptor versions are not closed. The graph is used for read-only classification and scene summary. It must not be treated as complete input to residency, aliasing or memory actuation. An elided clear remains an API-request work item in IR, so recorded clear count is not native executed-clear count.

Full passthrough transparency across all five engines and two workloads each remains an external acceptance question. The matrix records specific native/ARC2 captures and gaps; a startup, a Present count, or this owned five-test pass does not prove strict HRESULT, COM, visual and timing equivalence on every workload. No universal FPS claim or aggregate unknown-state reduction follows from these tests.
