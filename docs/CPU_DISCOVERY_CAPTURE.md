# Synchronized CPU discovery capture

Run `scripts/capture-cpu-work.ps1 -TargetPid <PID> -Output <fresh-directory>` from an elevated PowerShell after the user starts a supported game. The script records at most 60 seconds, stops early if the process exits or temporary ETW files reach 512 MiB, and owns a named WPR session. It leaves `cpu.etl`, `trace-stats.txt`, `events.txt`, `manifest.json`, and `analysis.json` together. `-SkipExport` keeps the ETL for a later export; `-MaxExportGiB` bounds the xperf text export (8 GiB default). Do not attach these files publicly: they can contain process names, paths and command lines.

WPR records process/thread, module load, sampled stacks, context switches and ReadyThread events, plus DXGI and DxgKrnl event providers in the same ETL session. `xperf -a dumper` preserves the ETL's relative microsecond clock. `xperf -a tracestats` supplies the UTC origin and lost-event/buffer counts. The analyzer accepts **only** files from one capture directory; it does not import a separate PresentMon run or infer a clock mapping from two recordings. A missing matching presentation/GPU event is explicit in `missing_evidence`.

`analysis.json` filters by target PID and process lifetime, resolves sampled program counters against time-scoped image ranges, and groups them into 4 KiB module-offset buckets. Module path, image checksum and PE timestamp are recorded so ASLR base addresses are not ranking identities. The bounded ranking requires hits in at least three 100 ms bins and uses sample count and recurrence. It does not infer invocation count, function boundaries, inputs, outputs, or safe specialization. Every ranked bucket remains `declined_no_region_semantics_or_dependency_proof` until a separate bounded instruction/dependency trace establishes those facts. PDB names are optional.

When the target starts inside the ETL, the analyzer requires a unique same-PID, same-image process-start event within 5 ms of the manifest creation time. Missing or ambiguous matches decline attribution. The first selected process end is immutable; a later owner of the same PID cannot contribute samples, module loads, scheduling or frame events.

`scheduling` reports observed running and ready-to-run intervals by thread ID and switch-out wait reasons. Boundary intervals are omitted. `present_intervals_with_samples` is only a temporal overlap estimate when this ETL has presentation event timestamps; it is not a causal critical-path measurement. GPU event rows alone do not establish GPU busy duration or ownership. Missing/lost events, a reused PID, incomplete module maps, or the two-million-sample parser budget are reported, never treated as proof of complete evidence.

Checks for this implementation: `wpr -profiles scripts/arc-cpu.wprp` validates the WPR schema without starting a recorder; `python -m unittest tests/analyze_cpu_regions_test.py -v` covers parser attribution and declines. An existing ETL can be exported with `xperf -i cpu.etl -o events.txt -a dumper` and analyzed with `python scripts/analyze-cpu-regions.py --capture <directory>`. The new provider profile still needs an actual elevated capture to confirm event availability and overhead on this Windows configuration.
