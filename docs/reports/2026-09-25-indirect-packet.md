# Indirect: корректная замена без ожидания метаданных CPU

Продолжение `555e55f`. Это **исследовательский адаптер Wicked по исходникам**, не автоматический перенос ARC.

Результат: GPU-упаковка используется настоящими indirect draw-командами; CPU не ждёт количества/смещения. В двух прогонах полный интервал между вызовами Present уменьшился **23,314 → 21,823 мс**. Частота вызовов — **42,89 → 45,82 Hz, +6,8%**. Это не замер display FPS и не результат коммерческой игры.

## Потребители метаданных

| Поле | Реальный потребитель | Как получено без ожидания GPU |
|---|---|---|
| Mesh | CPU: mesh, index buffer, материалы, PSO | Слово исходной 16-байтовой записи; проверяется одинаковость группы |
| LOD | CPU: `GetLODSubsetRange` | Override записи либо LOD из компактного sidecar производителя |
| Stencil | CPU: комбинация object/material stencil и BindStencilRef | Точное значение в sidecar |
| Force-alpha | CPU: вариант PSO | Для поддержанного класса доказан false; собственный material alpha-test остаётся исходным |
| Count | GPU: InstanceCount indirect-команды | Результат упаковки остаётся на GPU |
| Offset | GPU: StartInstanceLocation | GPU пишет смещение группы; в поддержанном классе одной группы оно равно нулю, CPU push-offset тоже ноль |
| First/end | Только диагностика | Единственная группа занимает исходный пакет 0..N |
| AABB | CPU forward-light mask | Этот класс проходов не перенесён |

CPU проверяет компактные записи и sidecar, **не обходит повторно ObjectComponent**. Sidecar расширен до 20 байт: transparency, LOD, alpha-test predicate, stencil/допуск, поколение. Запись происходит внутри существующего job производителя. Проверка пакета стоит около **0,248 мс** и включена в результат.

## Ограниченный класс

Поддержаны main/prepass, один mesh/эффективный LOD/stencil на пакет, 1–65 536 записей, до 64 subsets. Порядок CPU-сортировки и равных ключей не меняется.

Допуск производителя требует color alpha=1, alphaRef>=1, fadeDistance=FLT_MAX, конечный положительный radius. Проверка пакета требует конечную half-distance, актуальное поколение и корректные индексы. Поэтому объектный dither и force-alpha действительно нулевые; shader material alpha-test остаётся как в оригинале.

Mesh shaders, запрошенная тесселяция, wireframe, custom shaders, несколько групп и forward-light AABB merging здесь **не поддержаны**. Они сохраняют исходный CPU-путь. Несколько subsets поддержаны; их исходные PSO, материалы, indexCount/indexOffset и порядок команд сохраняются. Runtime дополнительно сверяет CPU-шаблоны статических аргументов с исходными значениями в месте вызова draw.

Offset=0 — реальное ограничение одного поддержанного класса, а не решение для произвольного числа групп. Нельзя распространять этот результат на все RenderMeshes.

## Защита версий данных

Удаление ожидания потребовало заменить прежнюю защиту:

- Три кадровых версии sidecar upload и таймеров.
- По два независимых слота main/prepass: record upload, draw templates, allocator, intermediate buffers, output, indirect args и timestamps.
- Собственный consumer fence ставится после отправки команд кадра и межочередных зависимостей. Значение — `frame+1`.
- Перед CPU-перезаписью upload, reset allocator и повторным использованием output проверяется **consumer fence**, а не завершение compute.
- Незавершённый слот даёт CPU fallback. Ожидания CPU для освобождения слота нет. Существующая синхронизация самого Wicked не удалялась.

Ранний upload текущего instanceBuffer, GPU-пакеты и draw используют одну native graphics queue. Прежняя повторная загрузка instanceBuffer пропущена. Порядок очереди сохраняет зависимости; завершённый compute сам по себе не разрешает перезаписать буфер, ещё нужный draw.

Тесты общего runtime-контракта проверяют занятый слот, старое поколение, различные mesh/LOD/stencil, override, недопустимую distance, границы массива и лимит пакета. В реальных прогонах busy-slot fallback не потребовался; принудительную GPU-задержку с заполнением всех слотов отдельно не вводили.

## Диагностическая проверка

Отдельный финальный oracle-прогон использовал **настоящую indirect-отрисовку**. После consumer fence проверены:

- **31 365 504 упакованных слова** против CPU-расчёта на тех же записях и объектах;
- метаданные группы;
- GPU-аргументы и **478 реально записанных indirect draw-команд**.

Несовпадений не было. Первые кадры могут не записывать draw, пока исходный PSO ещё компилируется; это сохранённое поведение оригинала. Диагностические readback и CPU-reference отсутствуют в производительном режиме. В нём возвращаются только timestamps; ожидание метаданных — **0 мс**. Полное сравнение финальных пикселей в этом этапе не выполнялось: проверялись точные входы отрисовки, команды и сохранение исходного выбора состояния.

## Сравнение полного кадра

Одна сборка, динамическая сцена Wicked Instances (18), прежнее движение/настройки, порядок CPU → indirect → indirect → CPU. Процессы по 20 секунд, лимит 60 секунд. Окно завершений кадров — 6–19 секунд. Сырые загрузочные кадры и все медленные интервалы сохранены; внутри окна выбросы не исключались.

| Режим | Средний интервал A / B, мс | p99 A / B, мс |
|---|---:|---:|
| Исходная CPU-упаковка | 23,470 / 23,158 | 29,273 / 28,813 |
| Асинхронный indirect | 21,746 / 21,901 | 27,978 / 27,945 |

Среднее двух запусков: **23,314 → 21,823 мс**, сокращение **1,491 мс / 6,4% времени**. Частота вызовов Present выросла **на 6,8%**. Оба запуска indirect быстрее обоих CPU-запусков; разница больше разброса средних этой короткой серии. Это повторяемый результат стенда в этих условиях, не обещание для других сцен/игр. Кадров >50 мс в steady-окнах не было.

В двух производительных прогонах реально заменено **195 902 080 записей**, записано **2 994 indirect draw-команды**. Проверка результатов не выполнялась в этих прогонах.

### Расходы и перекрытие

| Показатель | Исходный | Indirect |
|---|---:|---:|
| CPU Application Update, мс/кадр | 8,968 | 8,919 |
| CPU Application Render, мс/кадр | 12,525 | 11,274 |
| Полный интервал GPU-очереди, мс/кадр | 15,952 | 13,817 |
| CPU-подготовка ранней части/таймера, мс/кадр | 0,166 | 0,323 |

Новый GPU-таймер начинается **перед ранней загрузкой** и заканчивается после потребителей и межочередных зависимостей кадра. Он включает GPU idle/ожидание CPU. Уменьшение 15,952 → 13,817 не означает такое же уменьшение количества GPU-вычислений.

На один пакет в indirect:

- CPU-проверка компактных входов: **0,248 мс**;
- CPU copy/record/submit: **0,334 мс**;
- сохранённая CPU-подготовка draw: **0,017 мс**;
- GPU-вычисления: **0,980 мс**;
- GPU-копирование записей: **0,096 мс**;
- ожидание метаданных CPU: **0 мс**.

GPU-работа не исчезла и перекрывается с CPU. Складывать эти GPU-интервалы с CPU-временами для оценки кадра нельзя. Прежние 0,966 мс ожидания не использовались как обещанная экономия: эффект измерен на полном кадре.

Весь sidecar, preflight, шаблоны, ранняя загрузка и измерительная обвязка включены в сравнение. Первый запуск PSO/буферов учитывается в сырых данных, но не в steady-таблице. Его нельзя считать бесплатной инициализацией.

GPU: RTX 3060 Laptop, CPU: i7-11800H. Частоты/температуры/мощность приложены. Наблюдалось около **38–40 W** в CPU-режиме и **54 W** в indirect; power limit возвращался N/A. Настройки мощности не менялись. **Это не результат при гарантированном лимите 30 W.**
