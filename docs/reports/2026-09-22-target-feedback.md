# ARC: target feedback without image validation

New launcher sessions use `control_mode: target_feedback`, `maximize_fps: false`
and the user-selected `target_fps`. Existing configurations without the new field
retain the validated controller. Balanced/Aggressive now limit the available
mutation strengths in feedback mode; they do not certify image quality.

## Implemented behavior

- No image critic, quality snapshots, O/B/O sequence, A/B/A timing sequence or
  600-frame image-evidence lease in this mode.
- Present intervals drive the target controller. Two slow observations (>103% of
  frame budget), separated by about two seconds, permit one reduction. Three
  observations below 90% of budget permit restoring one previous setting.
- Bounded GPU profiling ranks supported compute passes; one mutation changes
  density, recognized independent sample count or mip offset. Existing policies
  remain enabled while profiling. No arbitrary geometry/RT or CPU scheduling changes.
- Sequential before/after observation can revert >3% (minimum 0.1 ms) regressions.
  This is not a causal performance experiment; moving content can confound it.
  Restoring detail may increase frame time as long as the target band remains met.
- Rejected changes have a 30-second cooldown. Lack of modified submissions also
  rejects a candidate. Submission counters are not advertised as per-pixel GPU proof.
- Shader, resource addressing, aliasing, queue and synchronization admission checks
  remain active. Changed technical context returns to original execution and
  rediscovers applicable work. Stop waits for restoration.
- No quality-certified performance hint is written by this mode.

## Telemetry and remaining limits

The controller logs current frame time/target, whole-process working set/private
commit, system physical memory, DXGI local-segment process usage and budget, plus
profiled supported compute cost and profile age. Local-segment usage is a DXGI
process accounting value, not an exact inventory of ARC-owned physical VRAM.

**Full game CPUft and GPUft remain unavailable in the generic adapter.** They are
explicit JSON null values. Supported compute times are not substituted for full
GPU frame time, and Present spacing is not called CPU execution time. Bottleneck
classification therefore remains unknown. RAM/VRAM are diagnostic inputs; this
iteration does not implement a new texture residency or system-memory actuator.

No image-quality guarantee, arbitrary-game target-FPS guarantee or new measured
speedup is claimed. The finite supported transformations can exhaust their range.
