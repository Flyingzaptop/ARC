# CPU producer → проверяемые локальные пакеты

Продолжение `de1e652`, 27 сентября 2026. **GPU-замены и нового ускорения нет.** Получен автоматически выбранный локальный пакет и установлен конкретный разрыв, не позволяющий отправить прежний фрагмент одним большим пакетом: вход обновляется внутри каждого callback, а результат нужен CPU до окончания того же callback.

## Что сделано

1. В момент аппаратного наблюдения записи восстановлены три caller frame через Windows unwind metadata. Сохранены машинный код и return PC; volatile-регистры caller не считаются восстановленными.
2. Анализ машинного кода нашёл настоящий цикл: начальный/конечный индекс из descriptor, инкремент, условие окончания, callback и atomic decrement после цикла. Шаг адреса не использован как размер задачи.
3. Автоматически выведены рецепты входной/выходной базы, индекс аргумента и forwarding через wrapper. В live-проверке сверяются фактические адреса непосредственно у производителя.
4. Ограниченный наблюдатель проверил три новых полных локальных задания. Последнее — holdout. Исходные callback, их побочные эффекты и atomic сохранялись.
5. Отдельное read/write-наблюдение выявило CPU-потребителей. Два соседних направления выбраны автоматически: производитель входа и непокрытый хвост перекрывающегося CPU/GPU-соответствия.

| Проверка | Результат итогового запуска |
|---|---|
| Границы пакетов | [512,768), [1792,2048), [3328,3584) |
| Элементы | 3 × 256 = 768 |
| Точный replay восстановленного выражения | 768/768, ноль несовпадений |
| Вход изменился между входом callback и производителем | 768/768 |
| Вход изменился после производителя до границы callback | 0/768 наблюдений |

Replay использует дерево происхождения из прежнего instruction replay, а не написанную по исходникам формулу. Для каждого пакета подставлены новые входные байты; общий скаляр взят из захваченного фрагмента. Это точная проверка наблюдений, не доказательство всех ветвей и всех арифметических режимов.

## Контракт и предел вывода

Поддержана локальная модель: callback вызывается для индексов `[start,end)`; output stride 576, input stride 32, читаемый span 28, результат 12 байт. Конкретные числа извлечены из кода. Глобальная граница задачи, количество таких заданий за кадр и полный набор потоков **не установлены**.

Участок содержит независимые скалярные вычисления по элементам, но это не делает независимыми всю callback-функцию и её побочные эффекты. Atomic после локального цикла обнаружен и сохранён; значение до decrement записано. Кто ждёт этот счётчик, где окончательная публикация и кто обеспечивает владение массивом — неизвестно. Не объявляем это доказанной синхронизацией всех потребителей.

Read/write-watch (24 события) обнаружил чтение выходного поля тем же потоком в той же функции после записи, затем чтения другими потоками. Это первые **наблюдённые** чтения, не доказательство отсутствия более раннего доступа. Поздно созданные потоки и все другие байты массива наблюдением не покрыты.

Исполнимые проверки наблюдателя: соответствие callback, баз данных и wrapper; реальный индекс каждого вызова; реальные input/output-адреса и условие ветви у производителя; полный проход диапазона; точный результат; чистое отключение. Они разрешают диагностическую проверку, **не замену**. Для замены отсутствует механизм удержания поколения/владения и весь граф обязательных потребителей.

## Расширение и причины остановки

- **Исходный фрагмент:** данные на входе callback устарели, а выход потребляется ещё внутри него. Сбор в начале пакета неверен; сбор после цикла слишком поздний для CPU-потребителя. Нужна переносимая область, включающая производителя входов и раннего потребителя, либо исходный CPU-путь.
- **Upstream:** для автоматически выбранного входного адреса наблюдались два writer PC: скалярная инициализация и 32-байтовая запись после вызова. Planner сохранил `ambiguous writer family`, не выбрал произвольный writer. Чтобы расшириться, требуется восстановить упорядоченную многостадийную цепочку и эффекты вызываемой функции, а не убрать проверку неоднозначности.
- **Соседнее поле:** следующий writer найден автоматически. Его источник — возврат прямого вызова. Ограниченный захват 2048 байт callee обнаружил SIMD-операции, корни и дополнительные условные вызовы. Линейный decode до первого `ret` явно не является полным CFG. Для эквивалентности нужен межпроцедурный анализ допустимых путей, точности/исключений и эффектов вызовов; прежний scalar single-function replay этого не доказывает. Живую замену не включали.

Таким образом, остановка вызвана установленной границей текущего метода — он закрывает локальное вычисление и loop bounds, но не цепочку нескольких производителей и ранних потребителей. Не утверждаем, что перенос этой цепочки невозможен или экономически невыгоден.

## Экономика и расходы исследования

**Стоимость устраняемой CPU-работы, GPU-время и чистая экономия остаются неизвестными.** Callback-интервалы содержат другую работу и аппаратные исключения. Их не используем для оценки полезности. Три выбранных задания не дают несмещённой частоты всех заданий/кадр. GPU-прототип не строился: актуальный доступный фрагмент пока не образует пакет с корректной границей входов/выходов; экономического отрицательного результата не заявляем.

Для одного наблюдённого пакета плотная копия полного входного span составила бы 7168 байт, результата — 3072 байта; это арифметика размеров, не замер transfer. Нельзя считать её допустимым маршрутом из-за описанного порядка готовности/чтений.

Окна наблюдения: write-watch 308,414 мс; slice 246,978 мс; batch 104,531 мс; consumers 302,694 мс; upstream 129,035 мс; adjacent 150,169 мс. Включают ожидание исполнения и расходы инструментации. Весь итоговый запуск 14,02 с. Максимальный Present-интервал после 5 с — **104,782 мс**; максимум всего запуска с загрузкой — **3667,254 мс**. Это пригодно только для режима обучения; сравнительного baseline для этих задержек нет.

Предвыделенные event buffers: 4 × 159744 + 729088 + 860376 = **2228440 байт**. Это не весь RAM ARC. Дополнительно ограничены размер выгружаемого кода, количество callee и события. Инактивные DLL/VEH остаются до выхода процесса для защиты от позднего exception dispatch.

Consumer: максимум 24 события; два соседних кандидата, по три записи; direct-callee: не более четырёх × 2048 байт и 256 линейно декодированных инструкций. Полная трасса процесса не собиралась.

Исходные binding snapshots остаются доказательствами предыдущего этапа и в локальной полной директории итогового запуска.
