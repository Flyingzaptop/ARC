# ARC: отбор CPU-цепочек, ограниченное раскрытие вызовов и GPU codegen

Продолжение `ea42326`. **Полезная живая CPU→GPU-замена не получена.** Исходная CPU-работа в приложении не пропущена; выигрыш кадра не заявляется. Выполнены несколько подэтапов: свежий отбор альтернатив, измерение функций и внутренних циклов, ограниченные захваты итераций и callee, генерация HLSL из восстановленного IR, изолированная GPU-проверка с полным обменом, основной и независимый стенды.

## Автоматический отбор и измерения

Использованы существующие `cpu_task_probe`, `discover-cpu-tasks`, `cpu_parallel_screen`, `select/run-cpu-contracts`. Новый параллельный профайлер не создавался. Перед началом прочитаны актуальные локальные инструкции; работа разделена между основным агентом и двумя GPT-6 Sol с отдельными файлами.

Свежий выборочный захват: 123 контекста, 9 функций, 8 пересекающихся кандидатов. Самплер остановил дальнейшее получение контекстов после одной медленной приостановки; суммарно собственные приостановки заняли 26,957 мс за 10,017 с. Пропущенная часть окна не превращается в нулевую работу.

Ранжирование автоматически выбрало упаковку с масками/смещениями и другой горячий цикл с вызовами. Для горячих неразобранных циклов теперь разрешено дешёвое измерение границ, даже когда подробная трансформация ещё не разрешена. Известно отрицательная экономика по-прежнему исключает повторную пробу при том же контексте. Замеры границ и попытки глубокого восстановления получили раздельные счётчики — серия измерений больше не расходует весь бюджет семантического исследования.

Нативный observer расширен режимами:

- повторные границы функции: до 32 пар, максимум 5 с общей активности и отдельный предел длительности вызова;
- границы внутреннего цикла: entry breakpoint отключается на время прохода, exit включает его для следующего прохода; **нет исключения на каждый элемент при замере**;
- одна итерация: ограниченный TF-захват до следующего входа в header;
- конкретный callee, автоматически выбранный из выполненного прямого вызова предыдущего захвата.

| Кандидат | Медиана окружающей функции, 16 наблюдений | Медиана самого цикла | Наблюдённые элементы |
|---|---:|---:|---:|
| Упаковка/расширение масок | 2,509 мс | 2,257 мс, 8 пригодных наблюдений | 65 344 |
| Фильтрация с вызовом добавления результата | 4,443 мс | 2,076 мс, 10 пригодных наблюдений | 65 344 |

Размеры получены из входного/выходного значения индукционной переменной и декодированного `add/cmp/backedge`, не из соседних адресов. Первое наблюдение каждого потока исключено из статистики полного цикла: подключение могло попасть в середину уже выполняющегося прохода. Эти исключения касаются **области измерения**, а не выбросов времени; остальные медленные проходы сохранены.

Время циклов всё ещё включает их вызовы, ожидания и доставку двух отладочных исключений. **Это ориентир/верхняя область для поиска, не сертифицированная стоимость устраняемой работы.** `GetThreadTimes` здесь квантован: 0 или 15,625 мс; ноль не трактуется как отсутствие CPU-работы. Глобальная частота вызовов/кадр неизвестна: наблюдались выбранные владельцы, параллельные вызовы могли пропускаться. Экономический selector принимает измеренную стоимость области только как подсказку ранжирования; полезная CPU-стоимость и выигрыш кадра остаются `null`.

Третья группа в отборе относится к функции с обнаруженными последовательными обменами. Эффективный параллельный алгоритм, сохраняющий порядок, не установлен; развитие точной сортировки не возобновлялось. Одна диагностическая серия её границ возникла при исчерпании старого общего счётчика попыток; этот дефект разделения бюджетов исправлен, она не используется как успешный результат.

## Что раскрыто внутри цепочек

`cpu_chain_cfg.py` обходит ветви worklist-алгоритмом, включая переходы после первого `ret` по другим путям, и ограниченно раскрывает прямые вызовы. Подключаемый PE проверяется по доступному SHA и всем перекрывающимся захваченным байтам. Непрямые вызовы, внешние эффекты, атомики и достигнутые бюджеты отражаются явно. Общий обзор достиг лимита 24 функций / 4096 узлов: он **не объявлен полным CFG движка**.

Несколько записей в один адрес больше не приводят к безусловному отказу: сохраняется наблюдаемый порядок отдельно по потокам. Инициализацией-кандидатом считается только распознанная непосредственная запись константы, а не просто первое событие. Финальность значения и порядок между потоками не выводятся из временной последовательности нескольких событий.

Расширен существующий training event: вместе с регистровым контекстом захватываются значения явно декодированных операндов памяти. Поддержаны обычные x64 stack effects `push/pop/call/ret`, косвенный call-operand и прямой `GS:[disp]` через TEB текущего потока. Отсутствие memory operand отличается от неизвестного покрытия. Неподдержанные формы сохраняют явный отказ.

Новые наблюдения:

- 79 событий одной итерации упаковки, включая проверку групп, численные условия, маску, запись результата и изменение счётчиков; все операнды в итоговом holdout прочитаны успешно.
- 111 событий альтернативного цикла с входом в вызываемую функцию. В первом захвате 51 инструкция ещё не имела карты памяти; этот результат сохранён с ограничением, не назван полным.
- Независимое последующее наблюдение прошло короткой ветвью фильтрации: 24 события. Это иной путь, а не подтверждение длинного пути.
- Из выполненного call автоматически выбран отдельный callee. Новый ограниченный захват: 48 событий, 32 memory operands, ноль непрочитанных/неописанных операндов исполнявшегося тела. Наблюдён путь добавления записи без роста контейнера. Ветка роста/выделения не сертифицирована.

Адреса, имена функций, смещения полей и размеры структур не подавались исследователю из исходников Wicked. Новые исходники движка не читались. Конкретный стенд, его бинарник и маршрут задавались человеком; выбор регионов внутри него выполнял ARC. Ручными остаются разработка поддерживаемых классов анализа и интерпретация ограничений в этом отчёте.

## Почему большие области пока не допущены

**Упаковка:** наблюдения показывают состояние между записями, условия границы группы, изменение смещений/счётчиков и численные преобразования. Нужен восстановленный эквивалент всей группы: предикаты → границы → сегментированные смещения → запись и метаданные, включая точную семантику FP16/сравнений. Разбор одной удачной ветви и отдельного bit-scan не доказывает эту модель.

**Фильтрация и добавление:** раскрыт быстрый путь изменения контейнера и заполнения записи, но не его полный протокол роста, владения и публикации. Нужно установить, какие поля являются состоянием контейнера, какие его потребители и как сохранить время жизни. Подмена этого условием «память приватная / конфликтов не увидели» запрещена.

Для обоих не закрыты:

- полная стоимость действительно удаляемой работы без сохраняемых эффектов;
- соответствие всех нужных входов уже существующим GPU-ресурсам и их актуальность;
- условия доступа/поколения выделений, публикация и сроки CPU-потребителей;
- полный GPU lowering составной операции и проверки поддержанного класса.

Это конкретный предел текущего метода: он теперь получает данные через нужные границы, но ещё не выводит из них контракт составной операции со счётчиками, памятью и потребителями. Новый контроллер включения/выключения живой замены не строился поверх отсутствующего допуска.

## Генерация GPU-варианта и экономика восстановленного класса

`scripts/cpu_ir_gpu.py` автоматически строит HLSL из существующего дерева происхождения. Поддержанный класс — scalar float32 `vaddss/vmulss` с полными листьями, точным порядком и выходной картой. Неизвестные выражения, смешанное происхождение байтов и неподдержанные численные значения отклоняются. Это **автоматический codegen ограниченного класса**, не готовая универсальная замена.

Программа GPU не написана вручную под Wicked. Входные слоты и gather offsets выводятся из IR и уже восстановленной адресной модели. Повторяющееся значение не объявляется неизменяемой константой. Данные пакуются в переиспользуемый upload buffer внутри измеряемого интервала; offline-подготовка снимков и компиляция отдельно от steady execution. Исходный малый фрагмент не выбирался снова как перспективный победитель: он использован для сквозной проверки нового codegen и закрытия ранее неизвестной изолированной экономики.

На RTX 3060 Laptop GPU побайтово совпали результаты реального holdout-пакета 256 элементов и граничных размеров 1/63/65. CPU-reference — 19 исходных захваченных инструкций, ограниченно проверенных и перенесённых в thunk на собственных буферах. Обёртка и её whitelist — вручную разработанный диагностический механизм, не автоматическое разрешение выполнить произвольный код. Раннее условие, производитель входов, потребитель и scheduler в этот CPU-замер не входят.

| Изолированный маршрут, 256 элементов | Медиана |
|---|---:|
| Исходные захваченные инструкции + вызов диагностической обёртки | 0,0014 мс |
| Упаковка в upload | 0,0016 мс |
| Запись команд | 0,0182 мс |
| Отправка | 0,03095 мс |
| Fence wait | 0,0516 мс |
| Копирование CPU-потребителю | 0,0010 мс |
| **Полный GPU-маршрут, измеренный напрямую** | **0,10335 мс** |
| GPU compute отдельно | 0,002848 мс |

Компонентные медианы не обязаны суммироваться в медиану полного пути. GPU-время входит в ожидание и повторно не прибавляется. Сравнение байтов вынесено за измеряемый интервал; полный readback нужен этому изолированному CPU-потребителю и остаётся в стоимости.

Маршрут малого фрагмента проигрывает примерно в 74 раза на этих снимках. Доминируют отправка/ожидание/запись команд. Устранить возврат для него нельзя без переноса установленного раннего CPU-потребителя. Этот отрицательный результат **не распространяется** на большие цепочки и не доказывает невозможность переноса вообще.

## Полное выполнение и второй стенд

Одинаковый owned-бинарник, режим `off`, маршрут и настройки; 8 с прогрева и 12 с измерения. В наблюдении использовался внешний CPU sampler, **не весь продукт ARC со всеми GPU-модулями**.

| Режим | Средний CPU through submission | Retired GPU span | Средний Present interval |
|---|---:|---:|---:|
| Исходный, до | 21,875 мс | 6,618 мс | 21,885 мс |
| Наблюдение CPU, без замены | 22,586 мс | 6,312 мс | 22,595 мс |
| Исходный, после | 22,147 мс | 6,238 мс | 22,158 мс |
| Допущенная замена | **Нет** | **Нет** | **Нет** |

Наблюдение медленнее средней двух baseline примерно на 0,574 мс / 2,6%. Серия короткая: это наблюдаемое различие, не точная причинная оценка каждого расхода. Ускорения нет. Present cadence не называется display FPS. CPU processing through submission не равен чистому времени вычислений потока; GPU span не покрывает произвольную внешнюю GPU-работу.

На независимом `arc-dynamic-city`:

| Режим | Средний CPU frame | Средний GPU frame |
|---|---:|---:|
| Исходный до | 1,117 мс | 0,875 мс |
| Наблюдение + отказ чужого контракта | 1,112 мс | 0,876 мс |
| Исходный после | 1,180 мс | 0,888 мс |

Найдено 0 кандидатов; чужой контракт отклонён с `initialization status 3`, игра продолжила работу и завершилась с 0. Это проверка отказа и подключения, не автоматический перенос. В короткой серии заметной регрессии наблюдаемого режима не выявлено; повторяемость на других рендерах не заявляется.

## Стоимость обучения, проверки, состояние стенда

Для training захвата резервируется около **60,3 MB буферов** плюс ограниченная карта памяти (до 32768 записей), библиотека и обычные runtime-расходы. Это не общий RAM игры. События сжимаются существующим changed-words writer. Отдельные захваты ограничены 32768 событиями, 3 с, полным нормальным выходом либо отменой; общий этап не ограничивался одной минутой.

Максимум Present после первых пяти Render завершённой загрузки: 27,05/31,96 мс для измерений циклов, 42,25/38,20 мс для holdout-итераций, 41,03 мс для раскрытого callee. Полные максимумы запусков с загрузкой составляли 2,31–3,49 с и не скрываются. Это данные режима обучения; они не обещают такую же цену постоянной игровой инструментации.

47 адресных Python-тестов прошли. Нативные проверки повторных границ и отмены сохранили результат, MXCSR и LastError; после отмены исходная задача продолжала выполняться. При проверке отмены `reason=8`, `trap_cleanup_pending=false`, все 300 контрольных вызовов совпали. Все использованные игровые стенды завершились штатно. Коммерческие игры не запускались. Канонический EXE Wicked восстановлен, SHA-256 совпадает с исходным.

## Воспроизведение и доказательства

`docs/evidence/cpu-chain-20260927/raw.zip`: сырые profile CSV, границы, исходные события, карты операндов, проверенный PE, GPU fixtures/HLSL/CSV и нативные результаты. `manifest.json` проверяет каждый файл; `result.json` содержит сводные показатели. Предыдущая цепочка CPU↔GPU остаётся в `docs/evidence/cpu-batch-20260927/raw.zip`; её полный захват повторно не собирался.

Основные команды Windows:

```powershell
cmake --build build --config Release --target arc-cpu-contract-capture arc-cpu-contract-fixture -j 2
python scripts/run-cpu-task-discovery.py <FRESH_SCREEN> --host build/producer-host.exe --runs original,discovery,original2
python scripts/run-cpu-contracts.py <PROBE> <FRESH_BOUNDARIES> --host build/producer-host.exe --mode boundary --limit 2 --ms 250 --boundary-samples 16
python scripts/run-cpu-contracts.py <PROBE> <FRESH_LOOPS> --host build/producer-host.exe --mode boundary --limit 2 --ms 250 --boundary-samples 16 --loop-regions
python scripts/run-cpu-contracts.py <PROBE> <FRESH_ITERATIONS> --host build/producer-host.exe --mode iteration --limit 2 --ms 3000 --events 32768 --loop-regions
python scripts/run-cpu-contracts.py <PROBE> <FRESH_CALLEE> --host build/producer-host.exe --mode callee --limit 1 --ms 3000 --events 32768 --callee-from <CAPTURE_WITH_OBSERVED_CALL>
python scripts/cpu_chain_analysis.py <LOOP_CAPTURE> <RESULT_JSON> --traces <ITERATION_CAPTURE> <CALLEE_CAPTURE>
```

GPU codegen, сборка и изолированные команды — `experiments/cpu-ir-gpu/README.md`. `experiments/cpu-batch/second_renderer.py` воспроизводит независимую проверку.

Итог: **автоматизировано больше исследования и построение GPU-кода для закрытого класса; реальной замены — 0; удалённой игровой CPU-работы — 0; новая GPU-работа в игре — 0; выигрыш полного кадра — не получен.** Следующая необходимая реализация — восстановление составной модели больших циклов (группы/смещения/изменяемое состояние), затем их memory/publication contract; просто ещё один наблюдатель или более агрессивный controller этого не заменит.
