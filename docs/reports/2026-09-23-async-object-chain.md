# Асинхронная цепочка Wicked: контрольный эксперимент

> **Поправка 24 сентября:** в этой исторической версии `replaced` захватывался по ссылке и выходил из области видимости до `Wait(ctx)`. Проверка до CPU-задач не исключала ошибку конечного списка. Эти замеры не подтверждают корректность исправленной сборки. См. [исправление и новые проверки](2026-09-24-replaced-lifetime-fix.md).

**Отрицательный результат по измеренной CPU-каденции.** Очередь уменьшила ожидание, но выбранная цепочка не ускорила приложение. Полный gate по GPU/display-completed кадрам не измерен. Это source-assisted эксперимент, не универсальный ARC.

## Реализовано

- Готовая матрица объекта → преобразование восьми углов AABB → центр → frustum/layer visibility → компактный список. Обновление самой матрицы остаётся CPU-работой.
- Один пакет на 65 536 объектов или два независимых по 32 768, каждый кадр; ограниченный пул слотов и отдельные fences. Это число отправленных пакетов, не доказательство одновременного исполнения GPU-ядер.
- Отправка после завершения зависимостей матриц; CPU продолжает остальные системы. Ожидание перенесено к первому потребителю — обновлению объектов. Нет использования предыдущего кадра или увеличения frames in flight.
- Статические границы/слои хранятся на GPU; в измерительных окнах их повторная пересылка равна нулю. Промежуточные результаты цепочки не возвращаются между GPU-операциями. Обязательные итоговые CPU-данные возвращаются.
- Подготовка входов распараллелена штатным jobsystem; последовательный прототип занимал около 2,64 мс, финальный — 1,18–1,27 мс. Это диагностическое сравнение разных прогонов, не изолированная оценка эффекта.

## Стоимость цепочки за кадр

| Компонент | 1 пакет, мс | 2 пакета, мс |
|---|---:|---:|
| CPU-подготовка входов | 1,24–1,27 | 1,18–1,20 |
| Упаковка и отправка | 0,93–1,02 | 1,10–1,17 |
| Ожидание у потребителя | 1,04–1,05 | 0,45–0,49 |
| Возврат и копирование результата | 0,64 | 0,54–0,58 |
| GPU-ядра, сумма | 0,062–0,064 | 0,087–0,096 |

GPU-время находится внутри общего исполнения/ожидания; его нельзя второй раз прибавлять к CPU wall time. Для двух пакетов приведены суммы по кадру, не среднее одной половины. Телеметрия и диагностическая запись входят в общую каденцию, даже если не входят в отдельный таймер.

Независимый интервал CPU после отправки последнего пакета — **0,037–0,044 мс**. Он вычислен от маркера последней отправки до входа в первое ожидание. Старый event `Chain independent gap ms` означает submit-to-consume gap отдельного слота и может включать ожидание/копирование предыдущего; он не выдан за независимую CPU-работу. Анализатор проверен регрессионным тестом на это различие.

Каждый кадр передаётся 4 МиБ матриц и возвращается примерно 3,25 МиБ результатов. Статические 2 МиБ метаданных загружаются при изменении, в тёплом окне — 0 байт. Основные D3D12-буферы примерно 18,5 МиБ суммарно: около 9,25 МиБ DEFAULT и 9,25 МиБ UPLOAD/READBACK; это расчёт размеров ресурсов, а не измеренный полный расход драйвера/RAM/VRAM.

Диагностический gate P: требуется 1.059 мс; консервативный выигрыш **-4.545 мс**. Полный GPU-completion gate не заявляется.
Диагностический gate Q: требуется 1.059 мс; консервативный выигрыш **-4.332 мс**. Полный GPU-completion gate не заявляется.

## Корректность и ограничения

Финальный oracle: 441 вызов, **28 835 841** набор границ/центров/флагов; ноль несовпадений. Границы и центры сравниваются побитно с исходными CPU-функциями на одинаковых входах. Маски и множества индексов — точно, включая отсутствие повторений. Проверены реальная стартовая сцена с одним объектом (неполная группа) и динамическая сцена 65 536 объектов. Параллельный порядок индексов не обязан совпадать. Oracle выключен в P/Q. Это эмпирическая проверка сцены, не доказательство всех IEEE/alias случаев.

Первые две попытки oracle завершились ошибками и исключены: пустой пакет на одном объекте и захват локального указателя по ссылке в отложенном задании. Исправлены соответственно ограничение числа пакетов числом объектов и захват указателя по значению. Общий POD-контракт исключает чтение результата через другой C++-тип. Неудачные журналы сохранены.

**Исправлено пояснение 24 сентября:** тип `int` в a4c3665 не устранял захват `replaced` по ссылке. Этот lifetime-дефект был исправлен только в последующем корректирующем проходе. Возврат 2 реально пропускает CPU-компактизацию, что отражено счётчиками `Chain CPU cull compact skipped`. Указатель результата живёт до существующего Wait(ctx), буферы слота не переиспользуются до fence.

Допуск ограничен исходниками стенда и простыми rigid meshes. Skinned/dynamic meshes, soft bodies, emitters, hairs и impostors исключаются. При несовпадении сцены/размера/frustum готовая видимость не используется. Пересоздание устройства и production stop/recovery не реализованы; GPU timeout/error завершает собственный тестовый процесс.

## Вывод и оставшаяся работа

Гипотеза о скрытии ожидания частично подтвердилась: два пакета примерно вдвое уменьшили wait. Гипотеза об ускорении приложения этой цепочкой — нет. Почти немедленный CPU-потребитель не даёт скрыть весь обмен, а подготовка входов и обязательный readback дороги.

Не перенесены обновление матриц, CPU LOD/ECS/материалы, подготовка draw/GPU-instance данных. Результаты, нужные этим CPU-потребителям, нельзя просто оставить только на GPU. Для следующего эксперимента нужна граница с существенно более поздним либо исключительно GPU-потребителем; одного увеличения очереди недостаточно.

Адаптивный регулятор доли переноса не добавлен после отрицательной экономической проверки. Нет достаточной синхронной телеметрии полного CPU/GPU critical path для управления одной разностью frametimes. Режим выключен по умолчанию, исходный EXE восстановлен. Универсальный экстрактор не разрабатывался.
