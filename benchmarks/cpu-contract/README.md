# Whole-call CPU contract training

This is a training/debug observer, not an admitted GPU optimization. It selects
entry points from the prior detector's `candidates.json` and pinned PE, merges
chained unwind ranges and validates bytes. No engine name or manually chosen RVA
is supplied to the selector. The fixture launcher is Wicked-specific; selection is not.

Build Release targets `arc-cpu-task-probe`, `arc-context-attempt-budget-tests`,
`arc-changed-words-tests`, `arc-cpu-contract-capture`, `arc-cpu-contract-fixture`.
Python dependencies remain those in `benchmarks/cpu-task-discovery/requirements.txt`.

On the existing local benchmark installation:

```powershell
C:/Python314/python.exe scripts/run-cpu-contracts.py C:/Users/r3d_flzp/ARC-Hardening-GPU/universal-optimizer/automatic-cpu-discovery-20260924-final/discovery/probe C:/Users/r3d_flzp/ARC-Hardening-GPU/universal-optimizer/cpu-contract-repeat --mode training --events 20000000 --ms 60000 --outermost --stop-unsupported
```

Use `--limit 1` for the first automatically ranked candidate, `--start N` to resume
selection, `--mode boundary` to observe entry/return without stepping, and
`--mode consumer` to follow the normal call's return into its continuation.
`--max-arg-span` is an explicitly labeled **observation-size hypothesis** used only
for exchange-shaped candidates. It does not establish argument types or admit a
replacement. The final full sorting capture does not use that size filter.

Each owned process has a hard timeout. When capture completes and cleanup is no
longer pending, the runner allows normal frames then posts WM_CLOSE. Prior binaries
are restored. Never use this launcher on commercial games; the user tests those.

To stop an active capture using the existing control transport:

```powershell
./build/Release/arc-dx12-probe-launch.exe --stop-auto <PID> ./build/Release/arc-cpu-contract-capture.dll
```

The DLL stays loaded to safely handle a pending trap. Stopping collection does not
rewind application work. Original CPU computation always runs in this implementation.

The last two commands apply only when the capture contains a suitable record/key

refinement computes byte coverage without the preliminary interval limit.

## Limits and trust boundary

Training explicitly permits slow frames. The ring, encoder and snapshots are bounded
below 64 MiB of explicit capture buffers on this host; trace disk is capped at 2 GiB.
Only one invocation is stepped. Capturing code includes user-mode callees; kernel/DMA
memory effects and all other threads' memory traffic are not covered. Concurrent entry
records and a sampled continuation are evidence, not proof of ownership.

The skip plan is generated by the included selector and validated against function bytes;
keep its manifest and generated files together. Do not treat an edited skip plan as
validated evidence. Register-only omissions are reconstructed from saved code; memory
instructions and control transfers are not designated pure by the selector.

The learning-mode report and `contracts.json` explicitly keep admission closed where
properties remain unknown. A complete observed invocation does not prove every input,
all execution paths, safe lifetime, caller liveness on other paths, or interchangeable
ordering of equal keys. No GPU scheduler or knowledge-sharing architecture is added.
